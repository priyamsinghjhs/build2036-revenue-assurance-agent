# Neon Postgres (free tier)

The Worker no longer queries D1 at runtime. Dashboards read pre-aggregated
summary tables in Neon over the `@neondatabase/serverless` HTTP driver
(Workers Free compatible; Hyperdrive is not used because it needs Workers Paid).

## Why we left D1

A single `SELECT` on the 14-way `v_ra_exceptions` UNION scanned ~2.4 million
D1 rows. `/api/dashboard/overview` then ran 12–18 `GROUP BY`s on the live recon
views, and `/api/system-map` added 18 more view scans (including
`v_ra_switch_clearing` over every switch log). Two diagnostic queries plus
overview loads exhausted the D1 Free **5 million rows-read / day** cap
(21 Nov 2026, ~15:00 UTC / 8:30 PM Asia/Calcutta).

The Neon design evaluates those views **once** in `refresh_ra_summaries()` when
the book is loaded. Every dashboard request reads only the tiny summary tables
(plus `ra_exception_rows`, ~200 rows) and is cached for 120s in the Worker
isolate and the Cache API.

## Free-tier budget

Neon Free (as of Nov 2026): **1 GB storage / project** (raised from 0.5 GB),
100 CU-hours / project / month, scale-to-zero after 5 minutes, 5 GB egress.
This book is ~1.4 MB in SQLite and should stay well under **0.5 GB** (and 1 GB)
in Postgres even with indexes and summary tables. Request-path queries are
point lookups, so compute stays in short bursts and can scale to zero.

Do not run `refresh_ra_summaries()` on every request.

## Apply (when `DATABASE_URL` is available)

```bash
# From cloudflare/
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f postgres/001_schema_and_seed.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f postgres/002_summaries.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f postgres/003_exec_automation.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f postgres/004_settlement_funding_acquirer.sql

# Then set the Worker secret (do not commit it) and deploy:
# npx wrangler secret put DATABASE_URL
# npm run deploy
```

`001_schema_and_seed.sql` is generated by `scripts/build_postgres.py` from the
SQLite migrations. `002_summaries.sql` defines the rollup tables and
`refresh_ra_summaries()`. `004_settlement_funding_acquirer.sql` adds the Settlement,
Funding and Acquirer domains (batches, funding instructions, acquirer entities)
and replaces `refresh_ra_summaries()` so those areas roll into the dashboard
summaries, heatmap and system map.
